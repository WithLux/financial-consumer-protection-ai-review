# 金融消保智能审查工作台 — MVP需求
版本0.1；2026-10-30；状态：产品需求与初步验收基线，尚未实现或实测。
英文名称：Financial Consumer Protection AI Review。
独立Demo，不代表TRS软件、授权或合作。本文的功能要求为本项目设计，不属于TRS已实现能力声明。

## 1. 用户、场景及边界
主用户：银行消保审查人员，查看材料、核验依据、修订及确认意见。
协作用户：产品/营销/业务材料提交人员，提供材料、产品类别、渠道、客群及审查背景；MVP由同一操作者录入，不实现企业审批平台。
维护者：维护法规版本、规则、模型配置及合成样本，确认来源效力与适用范围。
典型场景：审查金融营销宣传、产品介绍、客户告知材料中的疑似误导、收益承诺、关键信息缺漏等。
输出为辅助审查意见书。材料审查无法证明真实销售行为、客户适当性或全部业务合规；不能把“未发现问题”写为“合规通过”。
不实现交易限制、自动定责/赔付、银行内部系统接入、企业多级审批、扫描OCR、音视频审查和原版PDF批注。
公开Demo仅合成/授权脱敏数据；真实银行材料不得默认发送外部API。

## 2. 端到端业务流程
创建任务并录入材料类别、产品、渠道、客群及背景 → 上传文件 → 校验 → 分页/段解析 → 展示解析文本及覆盖限制 → 确认适用场景 → 规则检测 → 可选模型补充 → 验证引用及原文定位 → 合并疑似问题 → 人工逐条接受/驳回/编辑/补充 → 确认审查完成 → 导出Word → 删除或按Demo策略到期清理。
文件状态：uploaded / parsing / parsed / reviewing / awaiting_human / completed / failed。
模型状态独立记录：disabled / pending / succeeded / failed；规则完成但模型失败必须显示“仅规则审查完成”。
原材料重新上传生成新版本；旧定位不得沿用。更新意见后导出新版本，旧导出不代表最新意见。
本轮不假设后台已有正式审批或银行制度授权。

## 3. MVP功能和优先级
P0是端到端Demo发布门槛；P1是后续改进，非当前已完成清单。

| ID | 优先级 | 功能要求 |
|---|---|---|
| F01 | P0 | PDF/DOCX/TXT单文件上传，初始上限10MiB；校验内容与扩展名，随机服务端文件名，拒绝路径穿越及超限材料 |
| F02 | P0 | PyMuPDF解析文本型PDF；python-docx读取正文/表格；TXT支持UTF-8及UTF-8 BOM。扫描、加密、损坏、乱码明确报错或标示不支持 |
| F03 | P0 | 文本视图按页/段展示并保留原文映射；PDF标页码，DOCX标段落/表格单元格，TXT标行号；不承诺保留原版布局 |
| F04 | P0 | Python规则按产品/材料/渠道及日期过滤，支持上下文、否定、引用提示；结果称“疑似风险”，每项保留来源为规则或模型 |
| F05 | P0 | 服务端调用DeepSeek，环境变量配置；无密钥/超时/限流/错误JSON时保留规则结果并显式降级，不伪造模型成功 |
| F06 | P0 | 本地JSON法规库含名称、文号、机关、条款、原文/摘要、官方URL、公布/施行/失效日期、适用范围、核验日期及状态；未核验条目不得成为已确认依据 |
| F07 | P0 | 问题含quote、segment_id、start/end、类别、建议风险级别、理由、依据ID和具体建议；偏移必须与原文完全匹配，重复表述分别定位 |
| F08 | P0 | 只展示库中有效ID引用；模型未知ID或无原文支持的条款降为“依据待核实”，不得生成假链接；一条规则命中不自动证明条款适用 |
| F09 | P0 | 接受/驳回/编辑/手动补充；保留初始意见、人工最终意见、理由、操作者标识和时间；驳回不从审计记录消失 |
| F10 | P0 | SQLite任务及复核状态存储；刷新不丢人工修改；任务隔离、任务访问令牌及Demo访问保护，不能枚举他人材料 |
| F11 | P0 | python-docx导出标题、材料/任务版本、范围、解析限制、模型/规则状态、人工确认问题、原文位置、依据与链接、修改建议及辅助审查声明 |
| F12 | P0 | 待复核问题未处理时只导出带水印文案“未完成复核草稿”；正式Demo意见书必须逐项确认，且标明非银行正式签批文件 |
| F13 | P0 | Render公开HTTPS；密钥服务端保存，上传限额、调用限流、错误不泄密、日志不记录全文或密钥；任务删除覆盖原件、文本、结果及导出 |
| F14 | P1 | 历史检索、批量材料、意见对比、规则维护界面、原版PDF坐标批注 |
| F15 | P1 | OCR、音视频、复杂版式、组织权限、审批签章；先单独评估，不隐含在本MVP承诺中 |

## 4. 用户故事
US01：作为提交人，我需要明确知道解析哪些部分，避免扫描页/表格遗漏被误认为已审。
US02：作为审查员，我点击问题即可看到相应原文，能够分清同句多次出现的位置。
US03：作为审查员，我需要打开官方法规并核对条款、日期和适用场景，拒绝虚构依据。
US04：作为审查员，我可以驳回误报、修改建议或补充遗漏，并保留理由。
US05：作为审查员，我需要导出的Word与最后保存的人工意见一致，草稿和完成状态清楚。
US06：作为维护者，我能在无DeepSeek密钥时演示规则流程，且界面清楚说明限制。
US07：作为Demo使用者，我能删除任务，其他用户不能读取我的材料。
US08：作为维护者，我能更新法规版本而不改变历史任务所用证据快照。

## 5. 初步数据与接口约束
Task：随机ID、材料哈希/版本、产品渠道背景、解析覆盖、状态、创建/修改时间、规则库版本、模型版本与执行状态。
Segment：稳定ID、原文、页/段/行/单元格标识、顺序；定位偏移为Python Unicode码点，前端须显式转换，不混用JS UTF-16偏移。
Finding：问题ID、精确引文与段内半开区间[start,end)、来源、理由、依据ID、建议、原始结果、人工处理状态。
Regulation：F06字段，历史任务保存引用快照；法规正文作为证据，不允许模型自行修改库。
建议接口：POST /api/tasks；GET /api/tasks/{id}；POST /api/tasks/{id}/review；PATCH /api/tasks/{id}/findings/{finding_id}；POST /api/tasks/{id}/findings；POST /api/tasks/{id}/complete；GET /api/tasks/{id}/report；DELETE /api/tasks/{id}。鉴权、幂等、非法状态拒绝在实现时定义并测试。
FastAPI同源提供静态前端和API；无React/Vue、LangChain、外部向量库。

## 6. 主要风险、异常与处理
- 文件：ZIP解压炸弹、伪装格式、PDF加密/损坏/扫描；限制解析资源，明确失败，不输出“无风险”。
- 定位：跨段、重复句、Unicode、表格顺序及截断；只对验证通过的定位高亮，无法定位的结果另列待核实。
- 依据：过期、草案、不同产品范围；按版本与适用条件过滤，证据不充分显示待确认。
- 模型：幻觉、提示注入、超时、429、5xx及上下文超限；材料仅作为不可信数据，不执行指令；引用和引文服务端校验；长文不得静默截断。
- 人工操作：并发编辑、未保存导出、重复请求；版本冲突提示，导出只用已保存快照。
- 安全：上传内容XSS、SQL注入、任务越权、日志泄露、无限API成本；文本安全渲染、参数化SQL、访问检查及限额。
- 数据：Render临时文件系统可能导致SQLite丢失；选择可用持久化方案或明确临时Demo语义，不承诺跨部署持久化。
- 外部API：发送前明确数据用途和最小必要范围；无合法授权不使用真实材料。
- 法律：风险等级为审查优先级，非法律裁判；没有命中不等于合规。
- 本轮尚未验证实际准确率、效率和ROI，禁止作为宣传成果。

## 7. 初步验收标准
AC01：三种支持格式合成样本可解析；超10MiB、伪装、损坏、扫描/加密样本有明确反馈。
AC02：已定义测试规则的正例、否定例、引述例符合预期；规则命中可追溯，不能以此宣称通用准确率。
AC03：重复文本、中文、emoji及表格测试定位准确；quote与切片完全相等，未知偏移不强行高亮。
AC04：每条已确认依据均可回溯官方URL、准确条款及核验日期；未知模型引用被拒绝或标注待核实。
AC05：模拟模型成功、无密钥、超时、429、5xx及错误JSON；规则结果不丢失，状态真实可见。
AC06：接受/驳回/编辑/补充刷新后仍在；原始结果与人工最终结果分开保存。
AC07：未处理项阻止完成确认；草稿导出明确标识，完成导出包含保存版本和正确的人工意见，Word可打开且中文无乱码。
AC08：未知任务、无访问权限、并发版本冲突和非法状态有可理解错误；A任务令牌不能访问B任务。
AC09：仓库和前端不含密钥、上传原件或SQLite；日志不记录全文；删除任务后相关API无法返回数据。
AC10：Render HTTPS可访问并跑通“合成上传→解析→审查→人工复核→下载Word”；部署状态重启/持久化限制明确记录。
AC11：法规库为空时明确提示“无已核验依据”，不允许伪造正常完整审查。
以上为后续验证要求，本轮仅完成项目初始化和需求文档，尚未执行这些业务验收。
