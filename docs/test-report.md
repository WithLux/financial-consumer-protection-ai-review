## 5. 缺陷与修复

| 缺陷 | 复现 | 修复及回归 |
|---|---|---|
| 非上传API无统一请求体上限 | >1MiB登录JSON进入schema验证422 | 增加ASGI层1MiB上限，含分块流；413且不回显输入，测试通过 |
| Word生成可频繁占用CPU | 同会话第11次仍返回200 | 每会话10次/分钟，超限429；新增回归通过 |
| 否定/反面示例误标高优先级 | B材料命中高风险 | 近邻否定语境降低并解释“待人工判断”；非语义理解，跨句/长上下文风险保留 |
| SQLite删除后残留旧页/WAL风险 | 代码检查原未开启secure_delete/主动检查点 | 开启secure_delete、清理/删除后TRUNCATE检查点；删除与PRAGMA实测通过。不承诺SSD、备份或文件系统安全擦除 |
| 新会话页面无任务仍请求恢复导致401 | 静态检查恢复调用顺序 | 无当前任务ID不请求会话恢复；前端契约回归通过，浏览器控制台验收待补 |
| API缓存与响应保护 | 原缺统一响应头 | 增加API no-store、nosniff、DENY、防referrer泄露；响应头断言通过 |

## 6. 公开部署安全边界与剩余风险

- 密钥仅服务端配置；检查跟踪文件及变更，没有提交.env/数据库/运行材料。返回错误不回显完整输入或异常配置信息；代码审查未见记录完整材料的业务日志。生产日志采集配置仍待验证。
- 上传白名单、内容签名、大小及解析资源限制、无OCR、上传关闭/不保留原始文件；解析后文本仍在隔离SQLite保留至TTL，应只使用合成/授权脱敏材料。
- 外部AI必须显式授权，限制单次输入/输出、超时、并发、一次调用及全局日预算；重试失败调用也消耗保守预算。
- 新增120/min传输peer限制是单进程内存计数；Render代理可能使多个用户共享peer，需在实际代理链验证。它不能替代边缘WAF、分布式配额或防大规模恶意访问；重启清空短期限频。
- 仅支持单进程/单worker短期会话。Render临时磁盘丢失记录/预算后不应声称长期持久化；正式公网AI应配置可靠预算存储和平台成本上限。不得扩容多worker后继续依赖进程内锁/配额。
- 随机会话cookie、CSRF、owner过滤测试通过；生产HTTPS Secure cookie、同域、访问口令、会话隔离还需实际HTTPS环境验证。
- Prompt把材料当不可信数据，不允许执行工具/指令，返回需经过schema、引文和依据核验；这降低风险但不证明模型不受注入影响。语义误报漏检及人工误采纳风险仍存在。

**发布前必补**：干净环境全依赖安装与PDF/扫描PDF/损坏PDF；配置有效密钥后真实AI三类材料和注入对抗验证；可监听端口环境的完整浏览器业务闭环、离线/超时、1440/笔记本截图和控制台检查；Word办公软件视觉检查；Render HTTPS部署、代理限频及磁盘/重启/总成本验证。以上完成前不将本报告当上线许可。

## 7. 后续重跑

1. 安装requirements并运行Python/Node现有命令。无PyMuPDF时不得忽略skip直接批准上线。
2. 安装开发工具 `npm install --no-save playwright`、`npx playwright install chromium`（本轮未成功安装浏览器）。启动真实FastAPI，服务端配置口令；仅本地HTTP用COOKIE_SECURE=false。
3. 设置E2E_BASE_URL与E2E_ACCESS_TOKEN后运行 `npm run test:browser`。脚本必须连接HTTP服务，覆盖TXT、原文定位、驳回、草稿预览下载、双宽度截图、离线反馈；不冒充完整业务闭环。产物位于忽略的runtime/browser-qa。
4. 只有配置有效服务端AI密钥/开关时，设置E2E_USE_AI=true核对succeeded。完整人工接受/编辑/补充/最终确认和PDF/DOCX浏览器操作仍需扩展并实际运行；当前API闭环不替代该项。
